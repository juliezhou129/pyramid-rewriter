# 明确篇幅要求的计数与修订

仅在用户明确给出字数下限、上限或区间时执行；没有篇幅限制时，不增加计数流程，也不设统一的600字下限。

## 先确定计数范围与口径

- 用户指定范围和口径时，以用户要求为准，例如包含标题、只算正文、不含标点或某个软件的字数。不能用自己的口径替代用户指定口径。
- 中文未另行指定时，默认统计正文的非空白Unicode字符，含标点和数字，不计主标题、章节标题、Markdown标记、编辑前言、待核实事项、关键改动摘要和计数说明。它是字符口径，不冒充Word或飞书软件的字数统计。
- 用户明确只给上限或下限时，只检查该边界；给区间时同时检查两端。“简练”不能抵消明确下限。“约”表示目标篇幅，不擅自把它改成新的硬性区间。
- 多版本、多载体或分段有各自限制时，逐个检查；不能拿总长度代替各版本长度。

## 形成可核对的闭环

1. 先写完整草稿，再选出最终将交付的纯正文。去掉上述不计部分；正文中的加粗文字仍属于正文，只去掉格式标记，不删除文字。
2. 用本技能的 `scripts/check_length.py` 实际计数，记录范围、结果和计数口径。可以通过标准输入计数，无须联网或安装依赖：

   ```bash
   python3 <本技能绝对路径>/scripts/check_length.py --min 600 --max 800 --label 报告正文 <<'DRAFT_BODY'
   在这里放即将交付的纯正文，不放标题、格式标记或编辑说明。
   DRAFT_BODY
   ```

   脚本返回JSON：`count` 为实际字符数，`within_range` 为是否达标，`missing`／`excess` 为不足／超出量。退出码0代表达标，1代表未达标，2代表参数或读取错误。使用文件输入时传UTF-8纯正文文件；不要把完整带批注文档直接当正文计数。

3. 不足时，优先补足原材料能够支撑的论证：解释证据与结论的关系、限制对决策的影响、行动如何回应问题。不要新增事实、门槛、承诺或因果；不要靠重复、套话和空泛修饰凑数。
4. 超出时，先删重复、次要背景和冗长表达，保留必要事实、时间口径、样本限制和行动条件。
5. 修改后再次实际计数，直到满足边界。最后一次检查后，交付的正文应与被计数正文一致；之后改了正文就重新计数，不能引用旧草稿的结果。
6. 交付时在正文之外简短说明实际长度及口径，例如“正文672字符，含标点和数字，不计空白、标题及编辑说明”。用户只要纯正文或短文本无需附说明时，不增加说明段，将工具结果留在运行记录中。不得声称未经工具核对的精确数值。

默认脚本按Unicode字符计数；用户明确不含标点时加 `--exclude-punctuation`。其他口径（例如英文词数、指定软件字数）须使用能执行该口径的工具，不用字符数冒充词数。

材料不足以支撑指定篇幅时，不能为了达标编造或重复：说明无法同时满足的条件，并如实交付现有材料能够支持的版本。环境无法运行计数工具时，明确“未完成精确计数”，不凭估计声称已满足硬性限制。上述情况是未满足条件的透明说明，不视为已经通过篇幅验收。
